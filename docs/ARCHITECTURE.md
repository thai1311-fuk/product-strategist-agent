# Архитектура агента «Стратег Фабрики продуктов»

## Идея в одной фразе
Агент — это **процесс + реестр доказательств + граф зависимостей выводов**, а модели и субагенты лишь исполняют шаги. Поэтому результат можно проверить, работу — продолжить в любой среде, а при новых данных — точно найти, что пересматривать.

## Слои
```
┌──────────────────────────────────────────────────────────────┐
│ Пользователь (руководитель продукта): запрос, ворота, правки │
└──────────────┬───────────────────────────────────────────────┘
               │
┌──────────────▼──────────────┐   постоянные инструкции
│ AGENTS.md / CLAUDE.md       │   (правила, процесс, ворота)
│ скилл strategist (дирижёр)  │
└──────┬───────────┬──────────┘
       │           │ процедуры (skills)            субагенты (agents)
       │   research · data-analysis · interviews   collector (дешёвая модель)
       │   ux-review · product-strategy            synthetic-respondent (дешёвая)
       │   comms-strategy · decision-support       critic (сильная), consistency-checker (средняя)
       │
┌──────▼──────────────────────────────────────────────────────┐
│ scripts/sa.py — детерминированное ядро (Python, без зависимостей)
│ state · sources · evidence · conclusions · impact · validate │
│ decisions · cost · log · report · doctor                     │
└──────┬──────────────────────────────────────────────────────┘
       │
┌──────▼──────────────────────────────────────────────────────┐
│ projects/<slug>/ — состояние задачи (файлы, читаемые глазами) │
└─────────────────────────────────────────────────────────────┘
  методические знания: knowledge/methods/  шаблоны: templates/
  безопасность: lib/sanitize.py + хук guard.py + allowlist
```

## Разделение знаний (требование «Порядок в знаниях»)
| Что | Где | Меняется |
|---|---|---|
| Постоянные инструкции | AGENTS.md, .claude/skills, .claude/agents | редко, только разработчиком (guard.py спрашивает подтверждение) |
| Методические знания | knowledge/methods/ | редко |
| Материалы проекта | projects/<slug>/sources, data, interviews | при сборе |
| Состояние задачи | projects/<slug>/state.json, evidence, conclusions, decisions, log | постоянно |

Агент читает методическую карточку **перед этапом**, а не всё сразу — это экономит контекст и деньги.

## Доказательность
1. Источник → `sources.jsonl` + текст в `sources/S###.md`, обёрнутый как данные.
2. Утверждение из источника → `evidence.jsonl` с типом (факт / оценка / гипотеза / прогноз / допущение / синтетика) и дословной цитатой.
3. Вывод → `conclusions.jsonl` с `depends_on`.
4. Документы результатов ссылаются маркерами `[E###]`, `[C###]`.
5. `sa.py validate` механически проверяет: маркеры живые, у фактов есть цитаты, числа подкреплены, синтетика не доказывает спрос, вариантов ≥3 и есть «оставить как есть».
6. `evals/check_citations.py` выборочно сверяет цитаты с текстами источников (ловит выдуманные цитаты).

## Пересмотр при новых данных
Новые сведения → `evidence add` / `retract` / `supersede` → `sa.py impact` обходит граф (источник → доказательства → выводы → зависящие выводы → строки в outputs и decisions), помечает `needs_review` и показывает, что пересмотреть. Прежние ответы агента в доказательства не попадают: память между сеансами — это состояние и реестр, а не пересказ прошлого чата.

## Продолжение после перерыва
Всё состояние — в файлах. Хук SessionStart печатает `sa.py resume` в контекст нового чата; в Cursor/Codex то же самое делает правило «сначала выполни `sa.py resume`». Запись jsonl атомарная, действия журналируются с ключами — после сбоя видно, что уже сделано, и шаги не повторяются незаметно.

## Маршрутизация и стоимость
`config/routing.json`: сбор и извлечение (collector), модельные респонденты — дешёвая модель; синтез, варианты, стратегия, критика — сильная. Ошибка дешёвой модели, найденная валидатором или сверкой цитат, → повтор на сильной с записью в журнал. Расходы: хук Stop считает токены сессии из транскрипта, `sa.py cost report` сводит по этапам и моделям.

## Claude Code и Cursor
| Возможность | Claude Code | Cursor / Codex |
|---|---|---|
| Инструкции | CLAUDE.md → AGENTS.md | AGENTS.md, .cursor/rules |
| Процедуры | skills | агент читает тот же SKILL.md как документ |
| Субагенты | .claude/agents | выполняются в основном чате по тем же инструкциям |
| Продолжение | хук SessionStart | команда `sa.py resume` |
| Журнал и расходы | хуки PostToolUse, Stop | `sa.py log`, `sa.py cost add` вручную |
| Защита | хук guard.py + sanitize | sanitize в `source fetch` + правила AGENTS.md |

Ядро (sa.py) одинаково везде — поэтому проект переносится между средами без потерь.

## Почему так мало агентов
Субагент заводится, только если даёт измеримую пользу: collector — дешевле, critic — независимый взгляд (иначе модель защищает свои же варианты), consistency-checker — ловит расхождения продукта и коммуникаций, synthetic-respondent — изолированная роль без знания наших гипотез. Остальное — процедуры (skills) в основном контексте.
