# Сценарий демонстрационного видео (≤ 10 минут)

**Цель видео:** за 10 минут показать сквозной путь: запрос → работа агента → варианты → стратегия → продолжение после перерыва → новые данные и пересмотр → стоимость.
**Принцип:** зритель всё время видит, *что* делает агент, *на каком основании* и *сколько это стоит*. Длинные шаги (сбор, синтез) ускоряем ×4–×8 и подписываем «ускорено».

## Подготовка (до записи)

- Чистая копия репозитория; `projects/` пуст. Перед записью выполнить `python3 scripts/sa.py doctor`, его вывод должен быть зелёным.
- Экран: слева Claude Code (терминал, шрифт ≥ 16 pt), справа браузер для `report.html`. Разрешение 1920×1080, уведомления выключены.
- Заранее подготовить материалы демо (открытые: таблица CSV, 2–3 документа) и файл «новые данные» для последней части.
- Записывать **реальный прогон**, без монтажа ответов. Ускорять можно, вырезать ошибки нельзя: если агент ошибся и исправился, это стоит показать.
- Перед записью сбросить журнал расходов (новый проект), чтобы итоговая цифра в конце была честной.
- Титры: название, команда, «Claude Code + Python, без зависимостей».

| 1:10–1:50 | Агент создаёт проект (`sa.py new`), задаёт 3–5 уточняющих вопросов с вариантами ответа. Отвечаем коротко. | «Агент спрашивает только то, что меняет следующий шаг: какое решение и к какому сроку, кто получатель, какие есть данные, бюджет». | **уточняющие вопросы** |

Отвечаем «утверждаю, но добавь когорты по каналам». | «Первые ворота. Пока человек не утвердит план, агент не тратит деньги на сбор. Можно поправить план одной фразой». | **план (ворота)**, исправление пользователем |
| 2:30–3:30 | Ускоренно ×6: collector скачивает источники (видно `source fetch`, allowlist), `evidence add` с цитатами, расчёт когорт по CSV. Крупно: одна строка `evidence.jsonl` с полями `type`, `quote`, `source_ids`. Если сработал флаг `injection_suspected`, показать. | «Сбор идёт на дешёвой модели. Каждое утверждение записывается с типом и дословной цитатой: факт, оценка, гипотеза или прогноз». | **сбор с источниками** |

| 4:10–5:10 | `options.md`: 4 варианта, включая «оставить как есть» и «закрыть направление». Блок возражений от critic. Таблица оценки. Агент: «⏸ Выберите вариант». Отвечаем: «Берём B». | «Не меньше трёх реально разных вариантов. Независимый критик на сильной модели даёт сильнейшие возражения, чтобы агент не защищал свои же идеи. Выбирает человек». | **варианты + возражения → выбор** |
| 5:10–6:10 | Ускоренно: `product_strategy.md` (Коротко, отказы, North Star, риски) и `comms_strategy.md` (сообщение, таблица обещаний). Вывод consistency-checker: найдено расхождение (например, обещание, которого нет в продукте) → исправлено. `sa.py validate` → OK. | «Продуктовая и коммуникационная стратегии согласованы. Проверка нашла обещание, которое продукт не выполняет, и его убрали. Валидатор проверяет, что у каждой цифры есть основание». | **стратегии + проверка согласованности** |
| 6:10–6:45 | Пишем «стоп». Агент: «Остановился. Следующий шаг: …». **Закрываем окно Claude Code.** Титр «На следующий день». Открываем новое окно, пишем одно слово: «продолжи». Агент сразу показывает сводку `resume`: этап, следующий шаг, открытые вопросы, потрачено. | «Закрыли чат. В новом чате говорим "продолжи", и агент знает, где остановился: состояние хранится в файлах проекта, а не в памяти чата». | **перерыв → новый чат → «продолжи»** |
| 6:45–7:45 | Агент дописывает план проверки и запись решения D001 (метрика, срок, условия пересмотра). `sa.py report` → браузер: `report.html`. Пролистать: «Решение на одной странице» → прогресс → наведение на `[E…]` (подсказка с цитатой) → реестр доказательств, фильтр «гипотеза» → источники. | «Итог для директора — один файл. Сверху решение на одной странице, ниже основания. Гипотезы выделены пунктиром, их видно сразу. Файл открывается без интернета и печатается в PDF». | **report.html** |
| 7:45–8:50 | Пишем: «Новые данные: …» (поправка к одному из источников). Агент: `evidence supersede` → `sa.py impact` показывает цепочку: E012 → C004, C007 → D001, затронуты options.md, product_strategy.md. Выводы помечены «на пересмотре». Агент предлагает правку, человек подтверждает. Обновлённый отчёт: жёлтая плашка «Пересмотры». | «Решение принято, а данные поменялись. Агенту не нужно всё переделывать: по графу зависимостей он находит ровно те выводы, которые опирались на устаревший факт, и пересматривает их». | **новые данные → impact → пересмотр** |
| 8:50–9:35 | В отчёте раздел «Расходы»: итог, по этапам и моделям, полоска бюджета. Терминал: `sa.py cost report`. | «Вся работа стоила TODO $ из бюджета 5 $. Сбор шёл на дешёвой модели, стратегия на сильной. Видно, за что заплатили». | **стоимость** |
| 9:35–10:00 | README: блок «Ограничения», затем титр со ссылкой на репозиторий. | «Ограничения не скрываем: закрытых данных нет, синтетика не доказывает спрос, решение остаётся за человеком. Код и демо-проект — по ссылке». | — |

## Проверка перед публикацией

- [ ] Длительность ≤ 10:00.
- [ ] Видны все обязательные моменты: запрос, уточняющие вопросы, план и ворота, сбор с источниками, «знаем / не знаем», варианты и возражения, выбор, стратегии и согласованность, закрытие и новый чат с «продолжи», report.html, новые данные, impact, пересмотр, стоимость.
- [ ] Ускоренные фрагменты подписаны «ускорено ×N».
- [ ] Итоговая стоимость в кадре совпадает с `sa.py cost report` и с разделом «Время и расходы» в `docs/DESCRIPTION.md`.
- [ ] В кадре нет ключей API, личных данных, чужих закрытых материалов, уведомлений.
- [ ] Ошибки агента, если были, показаны или упомянуты и занесены в раздел «Ошибки и помощь человека».
- [ ] Субтитры на русском (автоматические, затем вычитанные).
