# Протокол сравнения: агент vs обычный чат с ИИ vs аналитик вручную

Цель — честно ответить: **насколько агент быстрее, дешевле или точнее исходного способа и какой ценой** (время человека, деньги, сложность). Протокол пишется до прогона; результаты — в `evals/results.md`.

## Что сравниваем
| Способ | Как получаем результат | Статус цифр |
|---|---|---|
| **A — агент** | Этот репозиторий в Claude Code (или Cursor), кейс как новый проект `sa.py new` | измерено |
| **B — обычный чат** | Тот же класс модели (та же сильная модель, что в `config/routing.json` для синтеза), веб-чат или API без инструментов проекта, **один промпт** (ниже) + вложенные материалы; разрешено ≤2 уточняющих ответа человека, чтобы уравнять с воротами агента | измерено |
| **C — аналитик вручную** | Экспертная оценка трудозатрат продуктового аналитика по этапам (часы на этап × число этапов), обоснованная декомпозицией работы; если кто-то из команды реально выполнил кейс вручную с таймером — это отдельная строка «измерено» | **оценка**, в таблице всегда помечена «оценка» |

Мы **не** выдаём оценку C за измерение. Если по способу C нет ни одного реального прогона, сравнение A↔C в выводах формулируется как «по оценке», а главное сравнение — A↔B.

### Промпт для способа B (дословно, одинаковый для всех кейсов)
```
Ты — опытный продуктовый стратег. Ниже запрос руководителя и материалы.
Подготовь: картину ситуации (что известно, откуда, чего не знаем), не менее трёх разных вариантов
решения с возражениями к каждому, рекомендацию, продуктовую и коммуникационную стратегию,
план проверки (что измеряем, с чем сравниваем, срок, риски). Указывай источник для каждого
утверждения. Отвечай на русском.
<brief.md>
<материалы>
```

## Изоляция (чтобы не подсмотреть ответ)
- Агенту — чистая копия репозитория **без папки `evals/`**; в проект кладутся только `brief.md` и материалы кейса (для A — также `data/*.csv`). Скрипт `make_data.py` и `expected.md` не передаются.
- Кейс D: материалы из `inject_later/` подаются строго по `cases/d/run.md`, одинаково для A и B.
- Каждый прогон — новый чат/сессия; память и прошлые проекты очищены (`projects/` пуст).

## Метрики
| Метрика | Как измеряем | A | B | C |
|---|---|---|---|---|

| Активное время человека, мин | время, когда человек читал/отвечал/копировал | таймер оператора | таймер | = времени |

| Доля утверждений с проверяемым источником | судья выбирает 20 существенных утверждений случайно (нумерует абзацы, берёт по генератору с seed), считает, у скольких есть ссылка, по которой можно найти подтверждение | ✓ | ✓ | н/п |

## Процедура
1. `python3 evals/make_data.py` — сгенерировать данные кейса A (seed фиксирован).
2. Для каждого кейса a–d и каждого способа A, B: прогон по разделу «Изоляция»; оператор записывает время, ответы на уточнения, расходы.
3. Собрать результат в единый вид (см. «Ослепление»).
4. Судья (LLM по `judge_prompt.md`) оценивает каждый результат **дважды** в разных сессиях; при расхождении >2 баллов по критерию — третья оценка, берётся медиана.
5. Человек-судья из команды, не участвовавший в прогоне, слепо оценивает хотя бы 2 пары (A/B на одном кейсе) — для проверки LLM-судьи.
6. Заполнить `evals/results.md`; вывод формулировать с указанием n и разброса.

## Ослепление
- Результат каждого способа приводится к одному виду: один markdown-файл «Результат» (для A — склейка `outputs/situation.md`, `options.md`, `product_strategy.md`, `comms_strategy.md`, `test_plan.md`, `decisions/*.md`).
- Удаляются признаки способа: названия команд (`sa.py`), пути файлов, упоминания «агента», «субагента», «этапа N/8», служебные блоки; маркеры `[E012]`/`[S004]` заменяются на сноски `[n]` со списком источников в конце; в ответе B ссылки тоже приводятся к сноскам `[n]`.
- Метки X/Y присваиваются случайно (подбросить монету / `random.choice` с записанным seed), ключ хранит оператор до конца оценки.
- Порядок показа судье — случайный; судья оценивает каждый результат отдельно (абсолютная шкала), а не попарно.
- Пункты *(процесс)* рубрики (2.4, 3.1, 3.2, 3.5) оцениваются **после** раскрытия по журналам — они неслепые, и это указывается в результатах.

## Как формулировать выводы
- «Агент быстрее/дешевле/точнее на X» — только по измеренным строкам, с n кейсов и разбросом.
- Указывать **цену**: время на настройку, активное время человека на воротах, стоимость токенов, где агент проиграл (например, медленнее чата на простых вопросах).
- Различия меньше разброса между двумя оценками одного судьи считать незначимыми.
