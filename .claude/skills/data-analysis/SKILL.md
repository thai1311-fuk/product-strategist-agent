# Анализ данных: воспроизводимо и с проверкой

Все расчёты — скриптами `scripts/analysis/*.py` (только стандартная библиотека), не «в уме» модели. Каждый скрипт пишет отчёт в `projects/<slug>/data/` (`--out` или `--slug`), печатает строку `ИТОГ:` и фиксирует входной файл с sha256, параметры и команду. Карточка: `knowledge/methods/research/data-checks.md`.

## Какой метод когда
| Вопрос руководителя | Метод | Скрипт |
|---|---|---|
| Можно ли верить этой таблице? Что с ней не так? | профиль данных | `profile.py` |
| Удерживаем ли пользователей? Стали ли новые когорты лучше после изменения? | когортный анализ | `cohorts.py` |
| Где теряем пользователей на пути к оплате? | воронка + интервалы | `funnel.py` |
| Окупается ли привлечение? Что будет при другой цене/оттоке? | юнит-экономика + чувствительность ±20 % | `unit_econ.py` |
| Сколько пользователей и дней нужно на тест? | расчёт мощности | `ab_size.py` |
| Совпадают ли цифры из разных источников? | приведение к общим единицам/периоду | вручную по чек-листу карточки + таблица расчёта в `data/` |
| Размер рынка | сверху вниз и снизу вверх, диапазон низкий/базовый/высокий | таблица `data/market_size.csv`: строка = множитель с маркером [E] |
| О чём жалуются / чего хотят (отзывы, интервью) | тематическое кодирование: темы → частоты → цитаты | вручную; частоты — качественный сигнал, не доля всех пользователей |

## Процедура
1. **Положи файл** в `projects/<slug>/data/` (без персональных данных: user_id обезличены, без ФИО/телефонов/e-mail; при ПДн — остановись и попроси обезличить). Исходник не правь.
2. **Зарегистрируй как источник:**
   ```bash
   python3 scripts/sa.py source add <slug> --title "Выгрузка событий, янв–окт 2026" --locator data/events.csv --kind table --reliability high --file data/events.csv
   ```
3. **Профиль — всегда первым:**
   ```bash
   python3 scripts/analysis/profile.py projects/<slug>/data/events.csv --key user_id,date --out projects/<slug>/data/profile_events.md
   ```
   Разбери каждое «подозрение»: смешение единиц/шкал, пропущенные периоды, смешение гранулярности, нарастающий итог, пропуски разного вида, дубли, выбросы. Исправимое — в **копию** `data/<имя>_clean.csv` с перечнем правок в отчёте; неисправимое — в «Чего мы не знаем» situation.md. Неясно, что значат единицы/определения, — спроси пользователя одним вопросом.
4. **Расчёт:**
   ```bash
   python3 scripts/analysis/cohorts.py --events projects/<slug>/data/events.csv --period month --out projects/<slug>/data/cohorts.md
   python3 scripts/analysis/cohorts.py --agg projects/<slug>/data/cohorts_agg.csv --out projects/<slug>/data/cohorts_agg.md
   python3 scripts/analysis/funnel.py --events projects/<slug>/data/events.csv --steps visit,signup,trial,pay --out projects/<slug>/data/funnel.md
   python3 scripts/analysis/funnel.py --agg projects/<slug>/data/funnel_agg.csv --out projects/<slug>/data/funnel_agg.md
   python3 scripts/analysis/unit_econ.py --csv projects/<slug>/data/monthly.csv --last 3 --margin 55% --out projects/<slug>/data/unit_econ.md
   python3 scripts/analysis/unit_econ.py --arpu 350 --churn 6% --cac 1200 --margin 0.55 --horizon 24 --out projects/<slug>/data/unit_econ_scn.md
   python3 scripts/analysis/ab_size.py --baseline 4.2% --mde-rel 10% --daily 5000 --variants 2 --out projects/<slug>/data/ab_size.md
   ```
   Имена столбцов отличаются — `--user-col`, `--date-col`, `--step-col`, `--map revenue=выручка,…`. Доли — `0.06` или `6%`; «6» без знака скрипт отвергнет.
5. **Результат → доказательство типа estimate** (источник — таблица, цитата — строка `ИТОГ` из отчёта, locator — путь к отчёту):
   ```bash
   python3 scripts/sa.py evidence add <slug> --type estimate --source S007 \
     --claim "Удержание на 1-й месяц — 60 % (когорты янв–фев 2026, 15 польз.)" \
     --quote 'ИТОГ: удержание k=1: 60,0 % (когорт 2, польз. 15)' \
     --locator data/cohorts.md --confidence medium
   ```
   `check_quotes.py` примет такую цитату, если `locator` указывает на отчёт в `data/`. Для решений приводи интервал/диапазон (Уилсон в воронке, чувствительность в юнит-экономике), а не одну точку.
6. **Уверенность расчёта:** `high` — полные чистые данные пользователя, проверенные профилем; `medium` — есть исправленные проблемы, малые когорты (< 30), короткий ряд, допущения по марже; `low` — параметры по аналогам/открытым источникам или неустранённые проблемы профиля.
7. Отчёт в `data/` — приложение; в `outputs/*.md` переноси вывод с маркером `[E###]` и одной фразой о главном ограничении.

## Обязательные проверки до вывода
- **Единицы:** руб./тыс. руб., с НДС/без, % vs п. п., доли 0–1 vs 0–100. ARPU и отток — за **один и тот же** период.
- **Периоды:** поток vs на дату, нарастающий итог, неполный последний период (скрипты его помечают), одинаковая длина сравниваемых периодов, сезонность.
- **Пропуски:** не нули; механизм (случайно/нет); расчёт с ними и без, если доля > 5 %.
- **Определения:** что такое «активный», «новый», «ушедший» в этой выгрузке — записать в `notes` источника.
- **Логика:** воронка не растёт к низу, когорта не больше своего размера, сумма частей = итог.
- **Малые числа:** когорты < 30 и конверсии с широким интервалом не годятся для выводов о различиях.

## Юнит-экономика: что сказать руководителю
- Явно перечисли допущения из раздела «Допущения» отчёта (маржа, постоянный отток, весь маркетинг на новых).
- Покажи, какой параметр сильнее всего двигает LTV/CAC — его уточнять первым (это вопрос в план или в test_plan).
- LTV/CAC — ориентир, а не закон: сравнивай с окупаемостью в месяцах и сроком жизни клиента.

## Качественные методы (отзывы, интервью, открытые ответы)
1. Выборка с правилом: платформа, период, число отзывов, сортировка (не «самые полезные» — смещение).
2. Кодовая книга: 5–12 тем с определениями; первые 30 текстов — открытое кодирование, дальше — по книге.
3. Частоты тем + 1–2 дословные цитаты на тему (без имён) → evidence: тема/частота — `estimate` с источником-выборкой, цитата — `fact`.
4. Вывод формулируй как «частая тема в отзывах», не «большинство пользователей».

## Готово, когда
- у каждого входного файла есть профиль и разобраны все подозрения;
- каждое число в outputs — с маркером на evidence `estimate`/`fact`, отчёт в `data/` содержит sha256 входа и команду;
- ограничения данных перенесены в «Чего мы не знаем» situation.md.

## Типичные ошибки
- Считать моделью вместо скрипта (не воспроизводимо, ошибки арифметики).
- Средний отток за год из месячных данных «на глаз»; сложение месячных MAU.
- Ненаблюдаемые ячейки когорт приняты за нули — удержание занижено.
- LTV по выручке вместо маржи; маржа не задана — скрипт подставит 100 % и пометит это допущением.
- Частота жалоб в отзывах выдана за долю недовольных клиентов.
