# Коммуникационная стратегия

Цель — не «красивое сообщение», а **одно сообщение, которое снимает главный барьер конкретной аудитории и обещает не больше, чем делает продукт**. Коммуникации следуют за продуктом: если продукт не готов выполнить обещание, это вывод для продуктовой стратегии, а не задача для текста.

## Вход (без него не начинай)
- `outputs/product_strategy.md` — выбранный вариант, сегмент, функции, условия (цена, пробный период, доступность), метрики, сроки. Если его нет или в нём нет сегмента и условий — верни задачу скиллу product-strategy.
- `outputs/situation.md` — задача клиента, альтернативы, данные воронки, чего не знаем.
- `evidence.jsonl`, `conclusions.jsonl`: `python3 scripts/sa.py evidence list <slug> --status active`.
- Шаблон: `templates/comms_strategy.md` → копия в `projects/<slug>/outputs/comms_strategy.md`.

Методы (читай карточку на своём шаге, не все сразу): `knowledge/methods/comms/` —
`barriers.md`, `positioning.md`, `message-house.md`, `claims-and-law.md`, `channels.md`, `message-testing.md`.

## Шаги
### 1. Аудитория и ситуация
Возьми сегмент **дословно** из product_strategy.md (другой сегмент = рассогласование). Опиши его через ситуацию и задачу: «Когда …, я хочу …, чтобы …» `[E###]`. Перечисли, что клиент делает сейчас (включая «ничего»).

### 2. Главный барьер (`barriers.md`)
1. Воронка решения сегмента: осведомлён → понял → считает подходящим → попробовал → платит → остаётся. Для каждого шага — данные `[E###]` или **Гипотеза:**.
2. Самый большой провал с данными → тип барьера (знание, понимание, релевантность, доверие, усилие перехода, цена/риск).
3. Раздели: что снимает коммуникация, что — продукт. Продуктовое — в раздел «Связь с продуктовой стратегией» и пользователю.
4. `python3 scripts/sa.py conclusion add <slug> --statement "Главный барьер: …" --depends-on E…,E… --kind insight`

Если барьер подтверждён только синтетикой или единичными цитатами — он **Гипотеза:**, и его проверка обязательна в разделе теста.

### 3. Позиционирование (`positioning.md`)
Альтернативы → уникальные атрибуты (только существующие к запуску) → ценность → кому важно → категория. Атрибут без `[E###]` вычёркивается. Формулу зарегистрируй: `sa.py conclusion add … --kind insight`.

### 4. Ключевое сообщение (`message-house.md`)
Как формулировать:
1. Возьми задачу аудитории (шаг 1) и главный барьер (шаг 2).
2. Сообщение = как продукт помогает с задачей **так, что барьер снимается**. Одна фраза, язык клиента, без превосходных степеней.
3. Тест на барьер: убери из фразы часть, отвечающую на барьер. Если сила не изменилась — сообщение барьер не адресует, переписывай.
4. Тест на продукт: каждое слово фразы должно найтись в таблице обещаний (шаг 5) с подтверждением.
5. Опоры (≤3): каждая снимает возражение и имеет reason to believe — **только `[E###]` типа fact (или estimate с оговоркой)**. Вывод `[C###]`, гипотеза или synthetic не являются доказательством.
6. Фундамент: цена, пробный период, автопродление, как отключить, ограничения — из product_strategy.md.
`python3 scripts/sa.py conclusion add <slug> --statement "Ключевое сообщение: …" --depends-on E…,C… --kind recommendation`

### 5. Таблица обещаний (`claims-and-law.md`)
Каждое утверждение из сообщения, опор и каналов → строка: обещание → чем подтверждено **в продукте** (функция/условие из product_strategy.md) → чем **в данных** `[E###]` → сила формулировки ≤ силы доказательства → юр. риск.
Проверяй: «лучший/№1/самый» без критерия и объективного подтверждения; «все/всегда/гарантируем» при выборочных данных; «бесплатно» при автосписании; скрытые ограничения; сравнения с конкурентами без методики. Не прошло → ослабь формулировку или перенеси в «что не говорим».

### 6. Роль каналов (`channels.md`)
1. Путь клиента и моменты контакта, где барьер острый и потребность «горячая».
2. Для 2–4 каналов: шаг пути/барьер, опора, призыв, метрика, ограничения. Остальные — «не используем на старте, потому что…».
3. Собственные каналы оператора (приложение, push, SMS, салоны, сайт): лимит частоты, согласие на рекламу по SMS/звонкам (38-ФЗ ст. 18), контрольная группа, риск выгорания базы.
4. Канал должен вести туда, где действие реально выполнимо в продукте.

### 7. Что не говорим и почему
Перечисли сильные, но неподтверждённые или рискованные формулировки, причину (нет доказательства / продукт не выполняет / юр. риск / синтетика) и замену. Этот раздел защищает от «улучшения» текста на следующих шагах.

### 8. Метрики и тест сообщений (`message-testing.md`)
- Главная метрика — **продуктовая** (та же или ведущая к той, что в product_strategy.md), с базой `[E###]`, целью и сроком.
- Промежуточные метрики коммуникаций — с объяснением связи с главной.
- Ограничители: отписки, жалобы, ранние отключения.
- Тест: уровень, варианты, контроль, выборка, срок, критерий успеха — заранее. Передай в test_plan.md (скилл research).

### 9. Связь с продуктовой стратегией
Заполни таблицу: сегмент, ценностное предложение, функции и условия, метрики, сроки → как отражены → расхождения.

### 10. Проверка согласованности
Вызови субагент **consistency-checker** (в Cursor/Codex — выполни его инструкцию из `.claude/agents/consistency-checker.md` сам, отдельным шагом) и передай пути:
`projects/<slug>/outputs/product_strategy.md`, `…/outputs/comms_strategy.md`, `…/evidence.jsonl`, `…/conclusions.jsonl`.
- **ДОРАБОТАТЬ** → исправь все «критично» и «важно»; если расхождение в продукте — сообщи пользователю и скиллу product-strategy, не подгоняй продукт под текст. Повтори проверку (не более 2 циклов, дальше — к человеку с открытыми пунктами).
- **ОК** → впиши статус и дату в шапку comms_strategy.md.
Для независимой атаки на стратегию в целом есть субагент critic (вызывает product-strategy или ты, если он ещё не смотрел comms).

### 11. Валидация и ворота
```bash
python3 scripts/sa.py validate <slug>
```
Ошибки (несуществующий/неактивный маркер, число без маркера) исправь и повтори. Когда готовы **обе** стратегии и вердикт ОК:
```bash
python3 scripts/sa.py stage <slug> strategy --status awaiting_human --next "Ждём решения: утвердить продуктовую и коммуникационную стратегии"
```
Покажи руководителю на одном экране: сегмент, барьер, ключевое сообщение, 3 главных обещания и их доказательства, каналы, что не говорим, главный риск. `sa.py gate <slug> strategy_approved` — только после явного «да» человека.

## Готово, когда
- Сегмент совпадает с продуктовой стратегией; барьер назван, подтверждён `[E###]` или помечен **Гипотеза:** с тестом.
- Одно ключевое сообщение, ≤3 опоры, у каждой опоры RTB `[E###]` (fact/estimate, active).
- В таблице обещаний нет строк «сила формулировки > силы доказательства» и нет обещаний без функции/условия в продукте.
- Фундамент (условия) присутствует во всех каналах с призывом к покупке.
- 2–4 канала с ролью; остальные исключены с причиной.
- Главная метрика коммуникаций связана с продуктовой; тест описан до запуска.
- Выводы зарегистрированы (`conclusion add`), consistency-checker: ОК, `sa.py validate` проходит.

## Типичные ошибки
| Ошибка | Как выглядит | Что делать |
|---|---|---|
| Сообщение-слоган без барьера | «Защита нового поколения» | Тест на барьер (шаг 4.3) |
| Обещание сильнее продукта | «Блокирует всех мошенников» при пилоте 95 % | Таблица обещаний, лестница смягчения |
| Все каналы сразу | Push + SMS + медийка + блогеры с одной метрикой «охват» | 2–4 канала с ролью и метрикой шага |
| Свой сегмент у коммуникаций | Продукт для родителей, реклама для молодёжи | Сегмент дословно из product_strategy |
| Синтетика как доказательство | «Респонденты высоко оценили» | Только как гипотеза для теста |
| Лечение текстом продуктовой проблемы | «Упростим восприятие» при 6 шагах подключения | Передать в продукт |
| Условия в мелком шрифте | «Бесплатно» без цены после пробного | Фундамент во всех продающих каналах |
| Метрика канала вместо продукта | Успех = CTR | Подключения → оплата → удержание + ограничители |
