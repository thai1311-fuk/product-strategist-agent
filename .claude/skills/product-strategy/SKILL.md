# Продуктовая стратегия: варианты → выбор → стратегия

Модель: сильная (см. `config/routing.json`). Вход — `brief.md`, `outputs/situation.md`, `evidence.jsonl`, `conclusions.jsonl`. Новых фактов на этих этапах **не выдумывай**: не хватает доказательства — помечай «Гипотеза:» и вноси в «что нужно узнать»; если без него нельзя различить варианты — верни проект на collect (`sa.py stage <slug> collect --next "…"`) и скажи пользователю, чего не хватает.

## Какие карточки читать (`knowledge/methods/product/`)
| Всегда | По типу запроса |
|---|---|
| `strategy-as-choice.md` (оси, обязательные варианты, отказы) | «Падает удержание/растёт отток» → `retention-diagnosis.md` |
| `premortem-steelman.md` (возражения, риски) | «Кому и как продавать» → `jtbd.md`, `competing-alternatives.md` |
| `unit-economics.md` (строки «выручка/затраты») | Много возможных проблем пользователя → `opportunity-solution-tree.md` |
| `north-star-metric-tree.md` (этап 5) | |

## Этап 4 — options

1. `python3 scripts/sa.py resume <slug>`; убедись, что synthesis = done и `outputs/situation.md` существует. `sa.py evidence list <slug> --status active` — рабочий набор доказательств.
2. **Диагноз в 3–5 предложениях** (Rumelt): где и у кого сломано, механизм, что не объяснено. Каждое предложение — `[E###]`/`[C###]` или «Гипотеза:». Диагноз-цель («надо поднять удержание») — не диагноз.
3. **Оси выбора.** Выпиши 2–4 оси из диагноза (аудитория/ситуация; модель ценности: подписка / бандл / бесплатно ради связи / партнёр; роль в экосистеме; уровень вложений).
4. **Варианты** (`templates/options.md` → `outputs/options.md`), 3–5 штук:
   - Вариант A **«Оставить как есть»** — прогноз траектории без изменений, затраты, честные плюсы.
   - ≥1–2 варианта **«изменить»** — разные комбинации значений осей.
   - Последний — **«Закрыть / свернуть»** (перевод на партнёра, функция другого продукта, закрытие с миграцией). Если закрытие действительно невозможно (регулятор, договор) — оставь вариант и запиши причину с `[E###]`; не выбрасывай молча.
   - Для каждого: где играем / как выигрываем, «что должно быть правдой», порядок экономики, первые шаги.
5. **Тест различия** (таблица в options.md): для каждой пары укажи ось, по которой варианты различаются **качественно**. Пара различается только параметром (цена, скидка, сроки, бюджет) → это один вариант; слей их и найди другую ось. Две «изменить»-альтернативы из одной ветки дерева возможностей — тактика, а не стратегия.
6. **Регистрация вариантов:**
   `python3 scripts/sa.py conclusion add <slug> --statement "Вариант B: семейное автокопирование для семей с детьми" --kind option --depends-on E004,E011,C002`
   В `depends_on` — только доказательства, на которых держится вариант (не «всё подряд»): это нужно для `sa.py impact`. Проставь полученные `[C###]` в заголовки вариантов. Варианты называй буквами (A, B, C, D), а не цифрами — меньше ложных срабатываний валидатора чисел.
7. **Возражения от critic.** Claude Code: инструмент Agent/Task, `subagent_type: critic`, задача: «проект projects/<slug>, проверь outputs/options.md, этап options». Cursor/Codex: прочитай `.claude/agents/critic.md` и выполни роль отдельным проходом, не глядя на свою рекомендацию. Вставь таблицу возражений critic в раздел каждого варианта **без смягчения**. Для каждого возражения ответ: *принято* (меняем вариант), *снято* (`[E###]`), *открыто* (→ «что нужно узнать»). Нарушения доказательности из отчёта critic исправь до ворот; блокирующие — обязательно. Серьёзные риски зарегистрируй: `sa.py conclusion add … --kind risk --depends-on C00X,E0YY`.
8. **Таблица оценки** — одна для всех вариантов, одинаковые строки: польза для аудитории (относительно альтернативы), влияние на выручку, влияние на затраты, риски (главный + ранний сигнал), неопределённость (низк./сред./выс. и почему), что нужно узнать (как, срок, цена), обратимость. Числа — только с маркером в той же ячейке/абзаце; допущения регистрируй как `sa.py evidence add <slug> --claim "Допущение: …" --type assumption`, чтобы у них был маркер.
9. **Рекомендация агента** (не решение): какой вариант и при каких условиях он перестаёт быть лучшим. `sa.py conclusion add … --kind recommendation --depends-on C00X,…`. Если неопределённость высокая у всех — честно рекомендуй «сначала узнать X» (дешёвый тест), а не выбор вслепую.
10. `python3 scripts/sa.py validate <slug>` → 0 ошибок. Затем
    `python3 scripts/sa.py stage <slug> options --status awaiting_human --next "Выбор варианта руководителем"`.
11. **Ворота option_chosen.** Покажи ≤10 строк: диагноз (1 строка), варианты одной строкой каждый с главным возражением, рекомендация, главное «что не знаем». **Жди.** После ответа человека:
    `python3 scripts/sa.py gate <slug> option_chosen --value C00X` → впиши выбор в раздел «Решение человека» options.md → `sa.py stage <slug> strategy`.
    Выбран «оставить» или «закрыть» — стратегия всё равно пишется (стратегия поддержки или сворачивания с метриками и отказами).

## Этап 5 — strategy

1. Проверь, что `gates.option_chosen` заполнен. Нет — вернись к шагу 11.
2. `templates/product_strategy.md` → `outputs/product_strategy.md` (если `sa.py new` его не создал). Заполни по порядку:
   - **Диагноз** — из options.md, уточнённый ответами на возражения.
   - **Аудитория и её задача** — ситуация + job story (`jtbd.md`), размер сегмента с `[E###]` или «Гипотеза:».
   - **Альтернативы** — пять классов из `competing-alternatives.md`, включая «ничего не делать» и самодельные обходы; у каждой — честная сильная сторона.
   - **Направление** — направляющая политика (1–2 фразы) + где играем / как выигрываем + согласованные действия (каждое объясняет, какую часть диагноза закрывает).
   - **Осознанные отказы** — «Мы НЕ делаем X, потому что … [маркер]; пересмотрим, если …». Минимум: отвергнутые варианты из options.md + 1–2 соблазнительных действия внутри выбранного варианта.
   - **Ценность ↔ деньги** — модель из `unit-economics.md`: каждая строка — факт `[E###]`, «Допущение:» с маркером или прогноз; сценарии и чувствительность; каннибализация и эффект на связь отдельными строками.
   - **Метрики** — North Star + 3–5 входных + защитные с порогом «стоп» (`north-star-metric-tree.md`).
   - **Риски и что их снимет** — из ответов на возражения critic и pre-mortem.
3. **Регистрация выводов стратегии** (чтобы `impact` находил их при новых данных):
   - диагноз → `--kind insight --depends-on E…`;
   - направляющая политика → `--kind recommendation --depends-on C<выбранный вариант>,E…`;
   - ключевые риски → `--kind risk`.
   Проставь полученные `[C###]` в соответствующие разделы.
4. **Передача в comms-strategy.** Заполни раздел «Связь с коммуникационной стратегией»: сегмент (тот же), задача, альтернативы, атрибуты с доказательствами, существенные условия (цена, пробный период, автопродление, как отключить, ограничения), **что продукт НЕ делает** (нельзя обещать), барьеры, которые снимает продукт, а не реклама. Затем запусти скилл `comms-strategy` (он пишет `outputs/comms_strategy.md`; ты его не правишь).
5. **Согласованность.** Claude Code: Agent/Task, `subagent_type: consistency-checker`, вход — обе стратегии. Cursor: выполни роль из `.claude/agents/consistency-checker.md`. Расхождения в своём файле исправь; в comms-файле — передай comms-strategy. Не более двух циклов; оставшиеся расхождения покажи человеку.
6. **Critic по стратегиям** (рекомендуется): тот же вызов, что в шаге 7 этапа 4, с указанием «этап strategy».
7. **Передача в test_plan (research):** раздел «Что проверить» — гипотеза «изменение X → метрика Y на ~Z за T», база, с чем сравниваем, защитные метрики. План проверки пишет исследователь.
8. `python3 scripts/sa.py validate <slug>` → 0 ошибок. `sa.py stage <slug> strategy --status awaiting_human --next "Утверждение стратегии"`. Покажи суть (направление, 3 главных отказа, North Star, главный риск). После «да»: `sa.py gate <slug> strategy_approved` → `sa.py stage <slug> test_plan`.

В Cursor/Codex (без хуков) после каждого этапа: `sa.py log <slug> --action options_done --target outputs/options.md` и `sa.py cost add …`.

## Критерии готовности
**options.md:** ≥3 варианта, есть A «оставить как есть» и «закрыть/свернуть» (или обоснование невозможности); тест различия пройден по осям; у каждого варианта — возражение critic и ответ; одна таблица оценки с одинаковыми строками; каждый вариант зарегистрирован как `option`; рекомендация отделена от решения; `validate` = 0.
**product_strategy.md:** диагноз называет трудность; аудитория описана ситуацией и задачей; альтернативы включают «ничего не делать»; ≥3 отказа с причиной и условием пересмотра; в модели нет числа без маркера/«Допущение:»; NSM связана с выручкой; у защитных метрик есть пороги; consistency-checker без открытых расхождений; все TODO убраны; `validate` = 0.

## Типичные ошибки
- **Стратегия-лозунг.** «Стать любимым сервисом семей» — нет диагноза, политики, действий. Тест: можно ли по тексту сказать, чего команда *не будет* делать в следующем квартале?
- **Варианты-клоны.** «Скидка 10 / 20 / 30 %» или «запуск в 1 / 3 / 10 регионах». Это один вариант с параметром.
- **Соломенное «оставить как есть».** Описан так, чтобы проиграть. Честно: ноль затрат на изменение, сохранение работающего, обратимость.
- **«Закрыть» пропущен** как немыслимый — жюри и заказчик требуют его рассмотреть.
- **Цифры без источника.** Любое число в абзаце без `[E###]` валидатор отклонит; оценки и прогнозы помечай типом.
- **Корреляция как причина.** «Подписчики реже уходят из связи» без контрольной группы — «Гипотеза:».
- **Отказы не названы** или названы фиктивные («не будем делать плохой продукт»).
- **Обещание сильнее продукта.** Comms обещает то, чего нет в разделе «направление»; это ловит consistency-checker, но предотвращает раздел «что нельзя обещать».
- **Синтетические интервью как доказательство спроса** — только как идеи для проверки.
- **Решение за человека.** Агент рекомендует; выбор — на воротах.
