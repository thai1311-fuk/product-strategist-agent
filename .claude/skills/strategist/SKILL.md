# Стратег: дирижёр процесса

Ты ведёшь работу по этапам из `AGENTS.md` (единственный источник истины об этапах, воротах и пересмотре — здесь только маршрутизация и управление) и подключаешь узкие скиллы. Этот скилл отвечает за три вещи: **старт**, **продолжение** и **управление** (стоп, уточнение, исправление).

## 1. Определи ситуацию
```bash
python3 scripts/sa.py list
```
- Пользователь продолжает → `python3 scripts/sa.py resume <slug>` и иди к `next_step`.
- Новый запрос → раздел 2.
- Непонятно, о каком проекте речь, → покажи список и спроси.

## 2. Новый проект (этап 0 intake)
1. Придумай короткий slug (латиница, дефисы), создай проект:
   `python3 scripts/sa.py new <slug> --title "<вопрос руководителя>"`
2. Заполни `projects/<slug>/brief.md` тем, что уже сказано.
3. Задай **только недостающие** вопросы, которые меняют следующий шаг (не больше 5, с вариантами ответа):
   - какое решение предстоит принять и к какому сроку;
   - кто получатель результата (руководитель продукта / топ-менеджмент / команда маркетинга);
   - ограничения: бюджет, сроки, что точно нельзя менять;
   - какие материалы есть (документы, таблицы, скриншоты, интервью) — только открытые и собственные;
   - бюджет на работу агента (по умолчанию 5 $).
   Если пользователь не знает — запиши как допущение и иди дальше.
4. `python3 scripts/sa.py stage <slug> plan --next "Составить план исследования"` → скилл **research**.

## 3. Маршрут по этапам
| Этап | Скилл / субагент |
|---|---|
| plan, collect, synthesis, test_plan | research (+ субагент collector на дешёвой модели) |
| таблицы и данные | data-analysis |
| интервью, модельные респонденты | interviews (+ субагент synthetic-respondent) |
| скриншоты, интерфейсы, пути | ux-review |
| options, strategy (продукт) | product-strategy (+ субагент critic) |
| strategy (коммуникации) | comms-strategy (+ субагент consistency-checker) |
| decision, monitor | decision-support |

Модели для этапов и субагентов — `config/routing.json`. Не подключай скилл, если он не нужен задаче: каждый шаг стоит денег.

## 4. Ворота (⏸ ждём человека)
На `plan_approved`, `option_chosen`, `strategy_approved`:
1. `python3 scripts/sa.py stage <slug> <этап> --status awaiting_human --next "Ждём решения: …"`
2. Покажи суть на одном экране: что предлагаешь, почему, что спорно, сколько уже потрачено.
3. После ответа: `python3 scripts/sa.py gate <slug> <ворота> [--value C###]`.

## 5. Управление по просьбе пользователя
| Пользователь говорит | Что делаешь |
|---|---|
| «стоп», «пауза» | Заверши текущее действие, `sa.py stage … --next "<точный следующий шаг>"`, коротко скажи, где остановились |
| «продолжи» (в том числе в новом чате) | `sa.py resume <slug>` → с `next_step` |
| «уточни задачу: …» | Обнови brief.md, `sa.py impact` не нужен; оцени, какие этапы устарели, верни проект на нужный этап и скажи об этом |
| «исправь вывод C004», «это неверно» | Если ошибка в данных → `evidence retract/supersede` → `sa.py impact` → пересмотри затронутое; если в рассуждении → исправь вывод и отметь «Пересмотрено» |
| «новые данные: …» | Скилл decision-support, раздел monitor |
| «сколько стоило», «что ты сделал» | `sa.py cost report <slug>`, `sa.py status <slug>` |
| «покажи результат» | `sa.py validate <slug>` → `sa.py report <slug>` → путь к outputs/report.html |

## 6. Прогресс
После каждого существенного шага — одна строка: «Этап 3/8 — картина ситуации: 9 источников, 31 доказательство, 4 пробела. Потрачено 0,42 $ из 5 $».

## Готово, когда
- `sa.py validate` проходит без ошибок;
- все ворота пройдены человеком;
- report.html собран и пользователь получил путь к нему;
- решение записано (decisions/), есть условия пересмотра.
