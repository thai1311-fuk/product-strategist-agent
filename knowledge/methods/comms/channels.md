# Роль каналов: путь клиента и моменты контакта

## Когда применять
- После message house: решить, **какой канал какую задачу решает**, а не «запустить везде».
- Продукт продаётся внутри экосистемы оператора (своя база абонентов) — главный ресурс в собственных каналах, главный риск — навязчивость.

## Типы каналов
| Тип | Примеры у оператора | Сила | Риск |
|---|---|---|---|
| Owned (свои) | Приложение (баннеры, карточка услуги), push, SMS, e-mail, сайт, салоны и их сотрудники, колл-центр, счёт/уведомления | Дёшево, точный таргетинг по базе, момент потребности | Навязчивость, отписки от push, жалобы на SMS, выгорание базы |
| Earned (заработанные) | Пресса, обзоры, блогеры без оплаты, сарафан, отзывы в сторах | Доверие | Не управляется, медленно |
| Paid (платные) | Performance, медийка, посевы, наружка | Охват вне базы | Дорого, маркировка (ст. 18.1 38-ФЗ), обещания проверяют строже |
| Shared (соцсети бренда) | Сообщества, каналы | Диалог, вопросы | Негатив публичен |
Модель PESO объединяет все четыре; для продукта внутри базы обычно начинают с owned и earned, paid — когда доказано, что сообщение конвертирует.

## Шаги
1. Опиши путь клиента сегмента: триггер потребности → поиск/узнавание → оценка → подключение → первое использование → привычка/продление. Для каждого шага — где клиент находится физически и в каком канале [E###] или **Гипотеза:**.
2. Найди **моменты контакта**, когда барьер наиболее острый и потребность «горячая» (например, сразу после подозрительного звонка, при оплате счёта, в салоне при покупке телефона родителю).
3. Для каждого канала заполни строку: задача (снять какой барьер / какой шаг воронки), какая опора message house, призыв к действию, метрика шага, частота/ограничение, риск.
4. Отбери 2–4 канала с ясной ролью. Остальные — «не используем на старте, потому что…».
5. Проверь согласованность с продуктом: канал ведёт туда, где действие реально выполнимо (кнопка подключения есть в приложении? салон умеет подключать?).
6. Установи правила частоты для owned: лимит контактов на абонента, исключение тех, кто отказался, контрольная группа без коммуникации (для честной оценки эффекта, см. `message-testing.md`).

## Мини-пример (пример, цифры вымышленные)
Сервис «Щит», сегмент — взрослые дети пожилых родителей.
| Канал | Роль | Опора | Метрика | Ограничение / риск |
|---|---|---|---|---|
| Приложение (карточка в разделе «Семья») | Понимание + подключение в один шаг | Подключаете из своего кабинета | Конверсия просмотр → подключение | Только у абонентов с привязанным номером родителя |
| Push после звонка с номера из базы мошенников | Момент потребности | Мошенники не дозвонятся | CTR, подключения, отписки от push | Не чаще 1 раза в 30 дней; согласие на уведомления |
| Салоны | Доверие: живой человек показывает журнал | Важные звонки проходят | Подключения в салоне | Обучение продавцов; запрет «впаривания» |
| Earned: материал о схемах мошенников | Знание о проблеме, не о продукте | — | Упоминания, переходы | Не обещать в PR больше, чем в продукте |
Не используем на старте: массовые SMS по всей базе (риск жалоб и ст. 18 без согласия), медийку (сообщение ещё не проверено).

## Особенности экосистемы оператора
- SMS, звонки, e-mail с рекламой — только с **предварительного согласия абонента** (38-ФЗ ст. 18 ч. 1; бремя доказать согласие — на рекламораспространителе). Служебное уведомление ≠ реклама: не маскируй рекламу под «важное сообщение».
- Push и баннеры в приложении: уважать настройки уведомлений; частые push → отключение уведомлений → потеря канала для всех продуктов.
- Собственные каналы — общий ресурс экосистемы: твой продукт конкурирует за тот же экран с тарифами и другими сервисами. Согласуй приоритет и частоту.
- Салоны: продавец говорит своими словами — дай ему опоры и фундамент (условия), иначе он пообещает лишнее.
- Нужна ли маркировка интернет-рекламы (ст. 18.1) в конкретном канале — уточнить у юриста.

## Частые ошибки
- «Все каналы сразу» без роли каждого — бюджет размазан, эффект не измерить.
- Охватная кампания до того, как продукт/онбординг готов принять поток.
- Метрика канала оторвана от продукта (CTR вместо подключений и удержания).
- Нет контрольной группы: эффект push приписывают тем, кто подключился бы сам.
- Игнорирование стоимости навязчивости: отписки, жалобы, негатив в сторах.
