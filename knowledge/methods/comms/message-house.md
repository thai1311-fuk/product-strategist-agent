# Message house: ключевое сообщение и доказательства

## Когда применять
- После позиционирования и выбора главного барьера: нужно одно сообщение и его опоры для всех каналов.
- Разные команды (CRM, SMM, салоны, PR) говорят о продукте по-разному.
- Нужно проверить, что каждое обещание чем-то подтверждено.

## Конструкция
```
            КРЫША: ключевое сообщение (1 фраза, язык клиента)
   ┌──────────────┬──────────────┬──────────────┐
   │ Опора 1      │ Опора 2      │ Опора 3      │   ≤3 опоры = причины поверить
   │ RTB [E###]   │ RTB [E###]   │ RTB [E###]   │   reason to believe — только из evidence
   └──────────────┴──────────────┴──────────────┘
   ФУНДАМЕНТ: условия и ограничения (цена, пробный период, кому доступно, как отключить)
```
- **Ключевое сообщение** = задача аудитории + снятие главного барьера. Не слоган: слоган пишут креативщики потом, из сообщения.
- **Опоры** — 2–3 аргумента, каждый отвечает на возражение аудитории. Порядок по силе для главного барьера.
- **RTB (reason to believe)** — проверяемый факт о продукте или данные: функция, условие, результат теста, независимая оценка. Только `[E###]` типа `fact` (или `estimate` с оговоркой). Гипотеза не может быть RTB — только кандидатом на проверку.
- **Фундамент** — существенные условия. Они не «мелкий шрифт», а часть сообщения (38-ФЗ ст. 5 ч. 7 — см. `claims-and-law.md`).

## Шаги
1. Сформулируй задачу аудитории: «Когда [ситуация], я хочу [прогресс], чтобы [результат]» (из situation.md, `[E###]`).
2. Сформулируй главный барьер (см. `barriers.md`).
3. Ключевое сообщение = как продукт помогает с задачей **так, что барьер снимается**. Проверка: если убрать барьер из формулировки, сообщение должно стать слабее. Если не меняется — сообщение барьер не адресует.
4. Подбери опоры: для каждой — возражение, которое она снимает, и RTB `[E###]`.
5. Выпиши фундамент из product_strategy.md: цена, период, ограничения, доступность по сегментам/регионам, дата запуска.
6. Иерархия по каналам: крыша — везде; опоры — по месту в пути клиента (push несёт одну опору, лендинг — все); фундамент — везде, где есть призыв к покупке.
7. Проверь «правило сильнейшего утверждения»: ни одна формулировка не сильнее своего RTB (было «в тесте 98 %» → нельзя «всегда»).

## Мини-пример (пример, цифры вымышленные)
Задача: «Когда родитель живёт отдельно, я хочу, чтобы его не обманули по телефону, не учя его новому».
Барьер: тревога «заблокируют нужный звонок» [E032].
**Крыша:** «Мошенники не дозвонятся до ваших родителей, а врач и курьер — дозвонятся».
| Опора | Снимает возражение | RTB |
|---|---|---|
| Блокировка в сети, без приложения | «Родитель не справится с настройкой» | [E014] техописание сервиса |
| Важные номера проходят, журнал виден вам | «Пропустит нужный звонок» | [E021] пилот: 2 % ложных блокировок; [E018] функция журнала |
| Подключаете из своего кабинета | «Надо ехать к родителям» | [E017] сценарий в приложении |
**Фундамент:** 30 дней бесплатно, далее 99 ₽/мес, отключение в приложении в один шаг, только для номеров оператора [E019].
Замечание: «2 % ложных блокировок» — это значит, что «никогда не пропустит» сказать **нельзя**; «врач дозвонится» допустимо только если врачебные номера в белом списке [E018].

## Частые ошибки
- Крыша — слоган без барьера («Защита нового поколения»).
- Пять опор: аудитория запомнит ноль. Больше трёх — признак, что позиционирование не выбрано.
- RTB = собственное мнение («удобно», «надёжно») или вывод агента `[C###]` вместо evidence.
- Синтетическая беседа как RTB («респонденты высоко оценили») — запрещено.
- Фундамент спрятан или забыт в коротких каналах (push/SMS).
- Разные крыши для разных каналов — это уже не одно сообщение.

## Первоисточник
Message house — рабочий инструмент PR- и корпоративных коммуникаций без единого автора (широко используется в агентской практике). Иерархия «главная мысль → аргументы → доказательства» — Barbara Minto, *The Pyramid Principle* (1987). RTB — элемент классического brand positioning statement (практика P&G). Формула задачи — job story (Intercom, Alan Klement, *When Coffee and Kale Compete*, 2016).
