# Анализ интервью: кодирование, аффинити, от цитаты к инсайту

**Когда применять:** после 3+ реальных расшифровок (уже обезличенных, см. `consent-and-anonymization.md`). Цель — превратить слова людей в проверяемые наблюдения и гипотезы, не потеряв связь с цитатой.

## Цепочка доказательности
```
цитата (дословно, R03, 12:40) → наблюдение (что человек делал/сказал) → инсайт (почему; что это значит для решения)
```
- **Цитата** — evidence `type=fact`, `quote` дословно, `locator` = файл + таймкод/строка.
- **Наблюдение** — обобщение по нескольким цитатам: «4 из 9 респондентов (R01, R03, R05, R08) …» — тоже `fact`, но про выборку.
- **Инсайт** — объяснение и следствие для решения → `conclusion` (kind=insight), `depends_on` на наблюдения. Пока не проверен на других данных — пишите «Гипотеза:».

## Шаги
1. **Подготовка.** Каждая расшифровка: ID респондента (R01…), сегмент, дата, интервьюер, длительность. Без имён и контактов.
2. **Открытое кодирование** (первые 2–3 интервью). Размечайте фрагменты короткими кодами-глаголами из жизни респондента: `платит_за_родственника`, `звонит_в_поддержку`, `боится_списаний`. Не кодируйте идеями продукта.
3. **Кодовая книга.** Сведите коды в список: код, определение, пример цитаты, когда НЕ применять. Дальше кодируйте по ней, новые коды добавляйте явно.
4. **Аффинити-группировка.** Выпишите наблюдения на «карточки» (одна мысль — одна карточка, с ID респондента), сгруппируйте снизу вверх по смыслу, а не по вопросам гайда. Назовите группу фразой от первого лица («Я не понимаю, за что списали»), а не ярлыком («Прозрачность»).
5. **Матрица «респондент × тема».** Таблица в `data/coding_matrix.csv`: строки — R01…Rn, столбцы — темы, ячейки — ID цитат. Показывает, у кого тема есть, а у кого её нет.
6. **Противоречия и исключения.** Отдельно выпишите, кто говорил обратное и почему. Отсутствие темы у сегмента — тоже находка.
7. **Инсайты.** Формула: *[сегмент] делает/испытывает [наблюдение], потому что [объяснение], поэтому для решения [следствие]*. К каждому — какие цитаты, сколько респондентов, что могло бы его опровергнуть.

## Частота ≠ важность
- Тема у 7 из 10 может быть мелким раздражителем; тема у 2 из 10 — причиной ухода к конкуренту.
- Важность оценивайте по: последствиям (деньги, отток, жалоба), силе эмоции и действия (человек что-то предпринял), связи с решением из research_plan.
- Количество в интервью — только **описание выборки** («3 из 8 опрошенных»), никогда не проценты рынка. Никаких «40 % пользователей» из 10 интервью.
- Распространённость проверяется опросом, аналитикой продукта, A/B-тестом — это следующий шаг в test_plan.

## Сколько интервью достаточно
- Ориентир насыщения для **однородной** группы: 9–17 интервью (обзор Hennink & Kaiser, 2022); в исследовании Guest et al. (2006) ~92 % кодов появились за первые 12 интервью.
- На каждый существенно разный сегмент — отдельная выборка (5–8 минимум для первых гипотез).
- Практический критерий: последние 2–3 интервью не добавили новых кодов, значимых для решения. Записывайте в анализ, на каком интервью появился каждый код.
- «5 пользователей» Нильсена — про юзабилити-тесты интерфейса, не про проблемные интервью.

## Пример
Цитата R04 (17:20): «Я уже третий раз пишу в чат, что не понимаю, откуда списание 99 рублей».
Наблюдение: 3 из 8 респондентов (R02, R04, R07) за последний месяц обращались в поддержку из-за непонятных списаний; двое из них (R04, R07) подключили запрет платного контента.
Инсайт (гипотеза): для этого сегмента непрозрачность списаний — главный источник недоверия, и он сильнее, чем интерес к новым сервисам; коммуникация новых подписок без прозрачной детализации усилит отток. Опровергнет: данные поддержки о доле таких обращений, опрос на большой выборке.

## Частые ошибки
- Группировать по вопросам гайда — получается пересказ анкеты, а не темы.
- Брать самые яркие цитаты и строить на них вывод (ошибка доступности).
- Смешивать слова респондента и интерпретацию аналитика в одной строке.
- Не фиксировать, кто НЕ упоминал тему, — завышение распространённости.
- Анализирует один человек, который проводил интервью и верит в идею: дайте второму кодировщику 2 расшифровки и сравните коды.
- Синтетические ответы в той же матрице — **запрещено**: держите их отдельно (`interviews/synthetic/`), они не входят в подсчёты.
