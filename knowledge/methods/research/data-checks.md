# Проверка данных: единицы, периоды, пропуски, сопоставимость

**Когда применять:** перед любым расчётом и перед сравнением чисел из разных источников (этапы 2–3, скилл data-analysis). Первый шаг для таблицы — `python3 scripts/analysis/profile.py <file.csv> --out projects/<slug>/data/profile_<имя>.md`.

## Чек-лист (пройди по порядку, найденное — в отчёт и в `notes` источника)
### 1. Единицы
- руб. / тыс. руб. / млн руб.; шт. / тыс. шт. — смотри шапку, сноски, порядок величины соседних строк.
- С НДС / без НДС; номинальные / реальные (с учётом инфляции) цены.
- % vs п. п. (рост с 10 % до 12 % = +2 п. п. = +20 %).
- Доли в одном столбце в виде 0,12 и 12 — смешение шкал.
- Валюта и курс: на дату или средний за период.
### 2. Периоды
- **Поток vs запас**: «за период» (выручка, продажи) vs «на дату» (абоненты, остатки). Их нельзя складывать одинаково: месячные абоненты не суммируются в год.
- **Нарастающий итог** (с начала года): Q1, 6М, 9М, 12М — чтобы получить квартал, вычитай.
- Календарный vs финансовый год; неполный последний период (месяц ещё идёт) — не сравнивай с полными.
- Смешение гранулярности в одном столбце (даты месяцев и дни вперемешку).
- Сезонность: сравнивай с тем же периодом прошлого года, а не с предыдущим месяцем.
### 3. Определения
- «Активный пользователь», «абонент», «клиент», «платящий» у разных источников разные (за 1/30/90 дней, хотя бы одна транзакция и т. п.). Найди определение — запиши в `notes`. Без него сравнение — `confidence: low`.
- Охват: Россия / города 100k+ / возраст 12+; выручка группы / сегмента / юрлица.
### 4. Пропуски
- Отличай: пусто, 0, «н/д», «-», «—». Ноль — значение, пусто — неизвестно. **Не заменяй пропуски нулями.**
- Механизм: случайные (сбой выгрузки) или неслучайные (не заполняют те, кто ушёл, — тогда среднее смещено). Неслучайные пропуски → сообщить, считать с ними и без, показать разницу.
- Доля пропусков > 20 % в ключевом столбце → вывод на этом столбце не выше `medium`.
- Пропущенные периоды в ряду (нет марта) — профиль показывает разрывы дат.
### 5. Дубли и выбросы
- Полные дубли строк и дубли ключа (user_id + date). Удалять только понятные технические дубли, число удалённых — в отчёт.
- Выбросы: правило IQR (вне [Q1 − 1,5·IQR; Q3 + 1,5·IQR]) или > 5 медиан. Сначала выясни: ошибка ввода (лишний ноль, единицы), реальное событие (акция, сбой), другая сущность (корпоративный клиент среди частных). Решение и причина — в отчёт; считай с выбросами и без.
### 6. Смена методики и разрывы рядов
- Росстат, Mediascope, компании пересчитывают показатели и меняют определения/охват. Ищи сноски «данные пересмотрены», «методика изменена с …».
- Не склеивай ряды через разрыв без пометки. Если нужно — используй период пересечения (обе методики за один год) для пересчёта, тип — `estimate`.
### 7. Сопоставимость перед сравнением
Две цифры сравнимы, только если совпадают: определение, единицы, период (и его тип: поток/запас), охват, методика. Иначе — приведи (расчёт) или пиши «не сопоставимо напрямую».
### 8. Логические проверки
- Сумма частей = итог (± округление); доли ≤ 100 %; воронка не растёт к низу; когорта не больше своего размера на старте.
- Порядок величины: ARPU 5 000 руб./мес. для массового приложения — подозрительно; проверь по отчётности.
- Парадокс Симпсона: общий тренд может быть противоположен трендам в сегментах — смотри разрезы, если смесь сегментов менялась.

## Как записать результат
- Таблица пользователя → `sa.py source add <slug> --kind table --locator data/<file>.csv`; в `notes` — хеш файла из отчёта profile.py, найденные проблемы.
- Каждое число из расчёта → `evidence add --type estimate`, цитата — строка «ИТОГ» из отчёта, `locator` — путь к отчёту.
- Обнаруженная проблема, влияющая на вывод, → в «Чего мы не знаем» situation.md.

## Частые ошибки
- Сложить абонентов по месяцам и получить «годовую аудиторию».
- Сравнить 9 месяцев этого года с 12 месяцами прошлого.
- Посчитать рост в % там, где нужен прирост в п. п.
- Молча выкинуть строки с пропусками (смещение выборки).

## Источник метода
C. Groskopf, «The Quartz guide to bad data» (2015); H. Wickham, «Tidy Data» (J. Stat. Software, 2014); D. Rubin (1976) — механизмы пропусков MCAR/MAR/MNAR; J. Tukey, «Exploratory Data Analysis» (1977) — правило IQR.
