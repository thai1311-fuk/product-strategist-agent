# Стратегия «Помощь до перебоя»: связь для близких и собственных устройств

> Документ по формату брифа партнёра [S001]: пять частей, расчёты рядом с решениями. Собран агентом из результатов проекта `family-connect` (situation, options, product_strategy, comms_strategy, test_plan). Числа брифа учебные; маркеры `[E###]` — доказательства с источником и цитатой, `[C###]` — выводы; **Гипотеза:** и «Допущение» — то, что ещё не проверено. Синтетические интервью — только гипотезы.

## Коротко
- **Первые клиенты:** организаторы семейных групп с общим пакетом интернета, которые помогают близким и узнают о перебое из просьбы о помощи [E008]; **Гипотеза:** чаще это пожилые родители и дети.
- **Проблема:** помочь близкому уже можно (добавить интернет из свободного остатка), но организатор узнаёт о перебое из просьбы о помощи — слишком поздно [E008]. **Гипотеза:** разрыв во времени, а не в возможности [C004].
- **Предложение:** сигнал организатору, когда у близкого осталось ≤ 10 % доли при свободном остатке в группе, и передача гигабайтов прямо из уведомления через уже существующую операцию; участник разрешает показывать только остаток [C010], [C008]. Плюс без разработки: подсказки и напоминания, чтобы новые группы доходили до первого полезного действия [C014].
- **Ожидаемый результат (прогноз, основной / менее благоприятный):** активные группы 5 707 / 5 316 вместо 5 000 без изменений [E073]; активация 52 % / 47 % вместо 45 % [E076]; в пилоте — доля групп с ограничением участника в 7 дней после первого подходящего случая ≈ 12 % → 8 % (12 % — Допущение по примеру брифа [E079]; размер пилота [E090]).
- **Честно о целях:** ни одна цель планового года в основном сценарии не достигается [E072]–[E076]. Прибыль +6 млн руб. первая услуга не даёт ни при каком сценарии [E067]; её закрывают только ≈ 2 400 новых платящих номеров [E069] — это отдельное решение руководителя (часть 4).
- **Просьба сегодня:** профинансировать только диагностику Q1 (аналитик и дизайнер по 0,5 ставки); пилот — решение в конце Q1 по заранее записанным порогам (часть 5).

## 1. Клиент и его проблема

### Где оператор может изменить результат
Кто первым замечает перебой? По брифу организатор о перебое порой узнаёт лишь из просьбы о помощи [E008]; кто замечает первым в большинстве случаев — неизвестно (пробел, вопрос гайда v2). Что он пытается сделать? Добавить интернет из остатка — операция есть [E008]. Когда помощь уже запоздала? В момент ограничения интернета у участника: дальше близкий без связи, пока организатор не узнает. **Последний момент, когда оператор ещё может помочь, — между «осталось мало доли» и «доступ ограничен»**: сведения о номере доступны оператору [E089]; Допущение: остаток обновляется раньше, чем вводится ограничение, — подтверждает владелец системы расчётов в Q1.

**Гипотеза (модельное интервью, не данные):** пожилой участник может вообще не сообщить о проблеме — «не хочет беспокоить» [E049].

### Один случай: как восстановим ход событий
Истории реального клиента в брифе нет [E014], поэтому описываем, что спросим и какие записи оператора восстановят случай:
| Шаг | Вопрос клиенту (гайд v2, `interviews/guide.md`) | Запись оператора |
|---|---|---|
| Последний момент, когда связь работала | «Когда у близкого последний раз точно был интернет?» | сессии передачи данных по номеру |
| Сигнал | «Кто первым понял, что связи нет? Как узнали вы — и через сколько?» | время ограничения и его причина |
| Причина | «Что вы видели в приложении о причине?» | остаток доли, свободный остаток группы, состояние счёта, результат платежа |
| Действия | «Что сделали дальше — шаг за шагом?» | обращения в поддержку, передача интернета, пополнение |
| Развязка | «Что случилось из-за того, что вы узнали тогда, когда узнали?» | время снятия ограничения |

**Сигнал ≠ причина.** «Близкий не отвечает» не значит «кончился интернет»:
| Версия | Какие сведения нужны | Меняет действие? |
|---|---|---|
| Исчерпана доля, в группе есть остаток | остаток доли и группы, причина ограничения | **да — наш случай:** передача прямо из уведомления |
| Пропущен платёж | состояние счёта, результат платежа | да — сигнал плательщику и пополнение, а не передача |
| Устройство выключено или разряжено | данные устройства (их нет [S001]) | да — оператор не поможет, сигнал не отправляем |
| Непонятное списание | начисления (отдельное согласие [E010]) | да — разбор начислений (кабинет C), не наша первая услуга |

### Почему этот приоритет первым
Отставание базового года: 4 000 активных групп при плане 5 000, 275 млн руб. при плане 282 [E003], [E004]. Разложение (скрипт `data/q1_gap.py`): **667 из 1 000 недостающих активных — меньше подключённых групп, 333 — подключённые группы реже действуют** (доля активных 61,5 % против 66,7 %) [E017]. Связь отставания по прибыли с перебоями неизвестна — **Гипотеза:** часть номеров уходит после повторных перебоев [C006].

Сравнение с серьёзной альтернативой — частым вопросом «за что списали»:
| | Перебой из-за исчерпанной доли (выбрано) | Непонятное начисление (альтернатива) |
|---|---|---|
| Сколько клиентов | группы с общим пакетом: Допущение — подходящий случай у ~10 % групп в месяц [E062] | любой плательщик может столкнуться; частота неизвестна |
| Повторяемость | **Гипотеза:** может повторяться при каждом исчерпании доли; частота неизвестна [E014] | **Гипотеза:** возможна при каждом списании; частота неизвестна |
| Тяжесть | близкий без интернета до помощи | время на выяснение, недоверие |
| Помощь вовремя | **да, если** остаток обновляется до ограничения (Допущение; сведения о номере у оператора есть [E089]) | после списания — только объяснение |
| Объём работ | малый: событие + уведомление + готовая операция | большой: кабинет с начислениями и согласиями [C011] |
**Какой ущерб важнее предотвратить:** потерю связи у близкого — она тяжелее для человека и её можно предотвратить до наступления; вопрос о начислении решается объяснением после.

**Какие сведения нужны и за какой период:** выгрузка ограничений участников по причине и свободному остатку за 3 месяца; повторы одного номера в течение 7 дней — один случай; доля ушедших номеров, у которых за 30 дней до ухода было такое ограничение, против той же доли у оставшихся; учёт обращений по темам с отделением повторных звонков по одному случаю. Только так видно и тех, кто в поддержку не обращался.

**Проверяемое предположение.** Если организатор получает сигнал до ограничения и помогает прямо из уведомления, доля групп с ограничением участника в 7 дней после первого подходящего случая снизится с ~12 % до ~8 % (**Гипотеза**; база — Допущение [E079], размер пилота [E090]). **Сменим приоритет, если** выгрузка Q1 покажет, что исчерпание доли при свободном остатке — меньше 40 % ограничений участников (Допущение до проверки 25–60 % [E015]) [C005].

## 2. Предложение и путь к клиенту

### Услуга глазами клиента
**Обещание:** «Узнайте, что у близкого кончается интернет, раньше него — и добавьте гигабайты из семейного остатка прямо из уведомления» [C019]. Выполнимо на тарифах с общим пакетом и правом передачи, при свободном остатке и с согласием участника на сведения об остатке [E010].

**Путь организатора:** приглашает близкого → видит, кто дал согласие на остаток → получает сигнал «У мамы осталось 0,3 ГБ из 3 ГБ. Свободно в группе 8 ГБ» → выбирает «1 ГБ / 3 ГБ / 5 ГБ» (предвыбран 1 ГБ) → «Подтвердить» — два нажатия → видит «кому и сколько добавлено, остаток семьи».

**Путь участника:** видит, кто пригласил и какие сведения хочет видеть: остаток — отдельное согласие, начисления — отдельное [C008]. При согласии на остаток организатор видит остаток доли в ГБ и факт ограничения; звонков, сообщений и местоположения не видит; начисления — только при отдельном согласии [E010]. Перечень проверяют юрист и безопасность до пилота. Не ответил — группа работает, сигнала по его номеру нет, напоминание через 3 дня. Отказался или отозвал — сигнал прекращается сразу, организатор видит «сведения недоступны» без причины.

**Одна операция до конца — передача интернета.** Возможна, если (1) тариф разрешает передачу, (2) организатор вправе распределять пакет, (3) свободного объёма хватает. После выбора объёма — «кому и сколько будет добавлено» → подтверждение → «выполняется, итог — в истории группы» → «добавлено 3 ГБ». Повторное нажатие до ответа системы расчётов блокируется ключом операции: второго вычета не будет. Если выбранный объём больше свободного остатка — предлагаем меньший; при остатке < 1 ГБ сигнала нет, о докупке сигнал не говорит (сервисное уведомление не смешиваем с предложением).

### Почему клиент выберет этот способ
| Чем пользуется сейчас | Что исчезает или становится раньше |
|---|---|
| Ждать просьбы / семейный чат | вмешательство **до** ограничения, без просьбы |
| Перевод денег через банк | не нужно платить ещё раз: гигабайты уже оплачены; банк подтверждает перевод, а зачисление на нужный номер проверяется у оператора; **Гипотеза:** ошибка номера при переводе [E051] |
| Встроенное у других операторов (делёж, лимиты, автопополнение) | сигнала до перебоя на страницах МТС, Билайна, МегаФона не найдено; уведомление Билайна с неясным условием проверяем [E100], [E097] |

**Параметры первого запуска:** порог фиксирован — 10 % доли; не больше 1 сигнала в сутки на участника и не ночью; организатор может выключить сигналы; сигнал только при свободном остатке ≥ 1 ГБ. Участники уже подключённых групп дают согласие однократным запросом в мае, до разбиения на ветки. Поддержка при звонке «у близкого нет интернета» показывает, как передать интернет сейчас.

**Состав первого запуска.** Уже есть: передача из остатка [E008], приложение, согласия участника [E010]. Добавить: событие «≤ 10 % доли при свободном остатке», уведомление, экран согласия на остаток, переход в операцию. Без чего обойдёмся на время проверки: настраиваемый порог, история сигналов, кабинет, сигнал плательщику о неоплате. **В тарифе** — без доплаты (предварительно: подтверждает владелец тарифа, утверждает руководитель); отдельно платить не предлагаем: польза для оператора — в удержании и активности групп.

**Гипотеза (модельное интервью):** часть плательщиков не доверяет платным услугам оператора [E052].

**Проверка удобства (Q1):** 8–10 организаторов решают «у мамы кончается интернет — помогите» привычным способом и через прототип, порядок меняется; фиксируем, кто справился без подсказки, где ошибка, сколько заняло. 8–10 участников пересказывают, что увидит организатор. Местоположение не определяем; совместных подписок нет.

**Что пригодится второй группе — владельцам своих номеров.** Событие о низком остатке и счёте, уведомление и переход к пополнению — те же. Путь короче: приглашать никого не нужно. Проверить заново: частоту остановок номеров устройств из-за неоплаты и порог «за 3 дня до списания» (**Гипотеза:** [E055]).

|---|---|---|---|---|---|

**Кому подходит первый сценарий.** Внутри 100 000 доступных домохозяйств — только группы с общим пакетом на тарифах с передачей и с согласием участника: Допущение — 60–80 % подключённых групп [E065]. Плательщик, у которого нет права видеть сведения близкого, — не наш первый клиент.

**От предложения до подключения (Допущение воронки [E077]):** без изменений организаторы создают 4 200 групп → приглашение принимают в 60 % (2 520) → первое действие за 14 дней — 45 % созданных (1 890). Люди останавливаются на шаге «приглашение принято» и на шаге «первое действие». Меры F: напоминание участнику принять приглашение (принятие 60 → 74 %, +588 групп) и карточка «проверьте остаток близкого» сразу после принятия (активация 45 → 52 %) [E071].

| Поддержка: сценарий при звонке «у близкого нет интернета» | в момент проблемы | звонящие организаторы | неизвестно | метка канала |
| Рекомендации клиентов | после пилота, Q3 | организаторы с успешной передачей | неизвестно | малый запуск |
**Двойной счёт:** подключение относим к способу, в котором создана группа (одна группа — один способ); вклад самой меры — только сравнением со случайной группой без меры (T2). Затраты на привлечение делим на прирост к группе сравнения, когда он установлен.

**Как сходятся числа (основной сценарий):** 6 500 + 2 520 обычных подключений + 588 от напоминаний − (1 020 − 100 сохранённых сигналом) выбывших ≈ 8 700 [E074], [E077]. Цель 12 000 — разрыв 3 300; первой услуге не приписываем все подключения года.

**Активность:** при 8 700 подключённых и доле активных 65,6 % — 5 707 активных [E073]. Рост доли с 62,5 %: сигнал (+2,1 п. п.: сигнал у ~7 % групп в месяц, реагируют 60 %, половина была бы активна и без него) и карточка после принятия (+1 п. п.) [E071]. Польза сигнала отдельно измеряется клиентским результатом — даже если человек реже открывает приложение (T1).

**Владельцы своих номеров:** в первый год обслуживание не меняем — прогноз остаётся 1 000 [E075]. Последствие: разрыв 1 000 до цели; решение о варианте D — в Q4 по данным о частоте остановок [E070].

## 3. Польза для клиента и прибыль оператора

**Главный результат:** близкий сохранил доступ к интернету. Признак — запись системы расчётов: было ли ограничение по причине «исчерпана доля» в течение 7 дней после первого подходящего случая. Открытие уведомления — не результат.

| Что измерить | Определение | Единица, числитель / знаменатель | Порог |
|---|---|---|---|
| Польза для клиента | доля групп с ограничением участника по исчерпанию в течение 7 дней после **первого** подходящего случая | группа; группы с ограничением / все включённые, в том числе не открывшие сигнал | −4 п. п. (≈ 12 % → 8 %) [E090] |
| Работа услуги | доля подтверждённых передач, исполненных правильно за ≤ 5 мин.; незавершённые — отдельно | операция | ≥ 99 % |
| Нежелательные последствия | двойное списание или вычет; сведения после отзыва согласия; ложные сигналы; перебой у другого участника | событие | стоп при: ≥ 1 случае / ≥ 1 случае / > 5 % сигналов / > 2 % передач |
**Почему −4 п. п., а не −3:** −3 п. п. (пример брифа) — 1 638 групп на ветку и 22 недели набора при 22 группах в день: итог не раньше ноября, раскатка в плановом году почти не успевает [E091]; −4 п. п. — минимум 882 группы на ветку и 12 недель при 22 группах в день [E090]. Порог записан в п. п. до старта. Если интервал включает и пользу, и её отсутствие — данных недостаточно, продлеваем набор.

**Пробный запуск.** Включаем группы, где тариф разрешает передачу, организатор вправе распределять, свободный остаток ≥ 1 ГБ и есть согласие на остаток. Первый подходящий случай — «≤ 10 % доли при свободном остатке», регистрируется системой расчётов одинаково в обеих ветках. Разбиение — **по группам целиком**, 50/50, считаем только первый случай группы, всех включённых. Набор с 1 июня: минимум 882, цель 1 200 групп на ветку, набор не дольше 1 октября. При 22 впервые подходящих группах в день минимум набирается за 12 недель [E062], [E090], 1 200 на ветку — примерно за 16 недель (2 400 / 22 ≈ 109 дней); если с учётом тарифов и согласий останется ≈ 15 в день — минимум за 17 недель, итог с 7 днями наблюдения в начале октября [E092]. Если раскатка сдвинется на ноябрь, вклад в плановом году 0,09 млн руб. вместо 0,12 — вывод не меняется [E093]. К концу Q2 будут известны исполнение операции, понятность и темп набора; клиентский результат — с конца августа до начала октября. Если только после анализа виден эффект на одном тарифе — новая проверка на новых группах с этим тарифом. При раскатке 10 % подходящих групп остаются группой сравнения (T3) [C015]. Ошибку оплаты или доступа сначала разбираем с владельцем системы.

**Сравнение с более простым способом.** Наш вариант и есть простой способ: сигнал + ссылка на уже доступную операцию. Дорогой кабинет [C011] обоснуем только если пилот покажет, что сигнала недостаточно, а обращения о начислениях — главная тема.

### Прибыль и окупаемость (скрипт `data/econ.py`)
База — 279 млн руб. без изменений; цель — 285; не хватает 6 млн = 12 000 доп. оплаченных месяцев по 500 руб. [E003], [E011].
| Слагаемое | Объём, цена, период | Плановый год, млн руб. |
|---|---|---|
| Доп. оплаченные месяцы от сигнала | пилот 1 200 групп с июня + раскатка с октября; снижение оттока = доля оттока, связанного с перебоями × реакция организаторов (календарь и сценарии — [E066]; Допущения [E103], [E065]) | +0,05 / +0,14 / +0,40 (слабый / основной / сильный) [E095] |
| Каннибализация докупки | 20 % случаев докупают сами × 30–50 % заменено передачей × 100 руб. [E065] | −0,01…−0,02 [E066] |
| **Итого вклад сигнала** | | **0,03 / 0,12 / 0,39** [E066] |
| Новые номера по приглашениям (F) | основной: 300 номеров с июля × 3,5 мес. × 500 руб. (Допущение [E071]) | +0,5 / 0 (основной / менее благоприятный) [E072] |
| Прямые расходы | push в собственном приложении | ≈ 0 |
**Граница решения.** Даже полная остановка оттока у групп с услугой дала бы 1,52 млн руб. в плановом году [E067] — цель +6 млн этим путём недостижима. Формула: вклад = 500 × Σ N × [(1 − c0·(1 − r))^k − (1 − c0)^k] − каннибализация. Решающее неизвестное — доля оттока, связанного с перебоями.

**Окупаемость.** Вложения 7 человеко-месяцев (разработка 3, тестирование 1, дизайнер и аналитик по 0,5 ставки на 3 мес.) × 0,4–0,6 млн руб. (Допущение [E058]) = 2,8–4,2 млн руб. Основной сценарий за 8 кварталов возвращает 1,37 млн и при вложениях 2,8 млн окупается к 11-му кварталу; окупаемость за 8 кварталов при вложениях 2,8 млн руб. (нижняя граница) требует снижения оттока у групп с услугой ≥ 17,9 % (≈ 30 % оттока, связанного с перебоями, при реакции 60 %) [E068]; при 4,2 млн руб. порог выше (не считали). **Поэтому деньги — по шагам:** сегодня только Q1; пилот — если T0 подтвердит причину и связь с уходом.

**Долгий срок (условный расчёт).** Ценность группы за время обслуживания = Σ по периодам (прибыль группы, если останется) × (вероятность остаться). Сравниваем только группы одинакового размера: группа с 4 номерами приносит больше группы с 2 просто из-за числа номеров. Данных об удержании групп нет — расчёт останется условным до T3.

## 5. Ресурсы, риски и решение руководителя

### Объём работ

| Руководитель направления | одобряет пилот, останавливает по порогам | — | весь год | — |
| Аналитик (0,5 ставки) | T0, исходные числа, расчёт выборки, мониторинг пилота | 1,5 в Q1 + далее | Q1–Q4 | выгрузки системы расчётов |

| Работа | Ответственный | Срок |
|---|---|---|
| С какой задержкой обновляются остатки, есть ли событие «≤ 10 %», какие тарифы разрешают передачу, где окончательный статус операции | владелец системы расчётов | середина Q1 |
| Какие сведения видны до согласия, после и после отзыва | команды личного кабинета и безопасности | конец Q1 |
