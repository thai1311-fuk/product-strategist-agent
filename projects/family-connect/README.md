# family-connect: демо по брифу МегаФона (режим full)

**Что это.** Полный прогон агента по официальному брифу партнёра со страницы задания — «Связь для близких и собственных устройств» (вымышленный оператор, учебные числа). Бриф: [`../../inputs/megafon-brief/brief.pdf`](../../inputs/megafon-brief/brief.pdf), текстовая версия — [`brief.md`](../../inputs/megafon-brief/brief.md) (PDF агент не разбирает, текст перенесён вручную).

**Открыть результат.**
- **Документ по формату брифа (пять частей, расчёты рядом с решениями):** [`outputs/brief_answer.md`](outputs/brief_answer.md); он же — первый раздел отчёта.
- Отчёт для руководителя (офлайн, с всплывающими цитатами): [`outputs/report.html`](outputs/report.html).
- Стратегии: [продуктовая](outputs/product_strategy.md), [коммуникационная](outputs/comms_strategy.md); [варианты с возражениями critic](outputs/options.md); [картина ситуации](outputs/situation.md); [план проверки](outputs/test_plan.md); решение [`decisions/D001-signal-staged.md`](decisions/D001-signal-staged.md).
- Расчёты — воспроизводимые скрипты (только стандартная библиотека): [`data/q1_gap.py`](data/q1_gap.py) (где отставание), [`data/econ.py`](data/econ.py) (прибыль, окупаемость, граница решения), [`data/forecast.py`](data/forecast.py) (пять строк брифа), `data/ab_size*.md` (размер пилота, `scripts/analysis/ab_size.py`).

**Итог в трёх строках.** Первые клиенты — организаторы семейных групп; проблема — помощь близкому доступна, но запаздывает; предложение — сигнал организатору при ≤ 10 % доли участника и передача гигабайтов прямо из уведомления, плюс меры активации без разработки. Деньги — по шагам: сейчас только диагностика Q1, пилот — по заранее записанным порогам. Честно: цель +6 млн руб. первой услугой не достигается ни при каком сценарии; это вынесено руководителю как отдельное решение.

**Цифры** (`sa.py status family-connect`, `sa.py cost report family-connect`): 36 источников (18 веб, 13 расчётных таблиц, 4 синтетических интервью, 1 бриф), 90 активных доказательств (48 fact, 16 estimate, 11 assumption, 9 synthetic, 6 forecast; ещё 13 заменены при пересмотрах и остаются в реестре), 21 вывод; 22,51 $ при бюджете 20 $ (перерасход 2,51 $) — **всё оценка** (`source=estimate`, см. ниже); активная работа агента ≈ 55 мин по журналу.

**Как шла работа (по журналу `log/actions.jsonl` и `state.json`).**
1. Intake: бюджет 15 $ — ответ человека. Режим full — рекомендация `sa.py route`.
2. Plan: варианты A–F, пороги до сбора данных, вопросы Q1–Q6.
3. Collect: 2 субагента collector (дешёвая модель) параллельно; цитаты проверены `check_quotes.py` (26 записей, 0 ошибок, 1 слишком широкое утверждение заменено; позже повторная сверка всех 48 активных fact — 0 ошибок, записана в журнал). 4 модельных респондента (дешёвая модель) → гайд v1 → v2.
4. Synthesis: разложение отставания скриптом; конкуренты: сигнала организатору не найдено.
5. Options: субагент critic (сильная модель) нашёл завышение экономики примерно в 3 раза (календарь, механизм эффекта) — пересчёт v2, вывод C010 пересмотрен, добавлен вариант F.
6. Strategy: consistency-checker (средняя модель) — 2 цикла: 2 критичных → 0 критичных; исправленное и открытое — в разделах «Проверки».
7. Test plan → решение D001 с порогами, триггерами и обязательствами.
8. Monitor: новые данные (страница МТС о ролях, S029) → `impact` → 6 выводов пересмотрены по порядку → D001 не изменилось, позиционирование уточнено.
9. Проверка фактов (отдельный субагент на сильной модели, после просьбы человека «ни один факт нельзя выдумывать»): 29 замечаний, из них 8 серьёзных. Главное — размер пилота был посчитан инструментом для **роста** доли, а метрика снижается: в `ab_size.py` добавлен флаг `--decrease` (с тестом), пилот пересчитан (минимум 882 группы на ветку вместо 1 181), ошибочные расчёты помечены и заменены (`data/ab_size*.md`). Также: цена у конкурентов, данные Билайна и МегаФона о просмотре остатков, уведомление Билайна с неясным условием — вынесено в обязательства D001, пороги T3 сведены к одному набору, «пожилые родители и дети» помечены как гипотеза. Затем — повторная сверка всех 48 цитат-фактов (0 ошибок) и второй проход проверки. Блоки «Пересмотрено: было / стало / почему» — в situation, options, product, comms.

**Что сделал человек, а что агент — честно.**
- Человек (в чате): бюджет 15 $, затем 20 $ (ответы на вопросы агента; `actor=human`).
- Ворота `plan_approved`, `option_chosen`, `strategy_approved`: человек сказал «делай как считаешь лучшим (я не разбираюсь в этом)» — агент закрыл ворота **по поручению** (`actor=delegated` — отдельная пометка, добавлена в агента в этом прогоне). После завершения человек в чате подтвердил все три решения (`actor=human`, запись `human_confirm`). Обе записи сохранены в журнале.
- Ответов «руководителя» за человека агент не придумывал: данных оператора нет, всё нужное — пробелы и допущения с маркерами.

**Почему расходы — оценка.** Сессия Claude Code была открыта из домашней папки, а не из папки проекта, поэтому хуки проекта (`.claude/settings.json`) в ней не работали. Агент вёлся как в среде без хуков: `session start/end` и `cost add`. Расходы координатора (Opus) оценены по числу вызовов и среднему контексту; расходы субагентов — по числу токенов, которое показывает среда (разбивка на вход и выход — оценка). Координатор и обе проверки фактов работали на сильной модели (Opus — 21,31 $ из 22,51 $); координатор шёл на ней на всех этапах, включая те, где `routing.json` рекомендует среднюю или дешёвую; на дешёвую уходили только субагенты сбора и модельные респонденты. Это главная причина цены — для экономии запускайте `claude` в папке проекта на средней модели (см. README, режимы).

**Ошибки агента, найденные в этом прогоне и исправленные в коде (с тестами):**
- Страницы в windows-1251 без charset в заголовке сохранялись «кракозябрами» (S016, pravo.gov.ru) — `_detect_charset` в `scripts/lib/evidence.py`, тест `tests/test_charset.py`; S016 не используется.
- Изменение бюджета всегда записывалось как решение человека — теперь пишется реальный исполнитель (`tests/test_delegated_gates.py`).
- Валидатор не учитывал более позднее подтверждение ворот человеком — исправлено (тот же тест).
- Отчёт не умел показывать документ в формате заказчика — добавлен раздел для `outputs/brief_answer.md`.
- Отчёт показывал пересмотренный вывод зачёркнутым, как отменённый, хотя ядро считает его действующим — исправлено в `scripts/lib/report.py`.
- `ab_size.py` умел считать размер выборки только для роста доли; для снижения (наша метрика) добавлен флаг `--decrease` и тест. Ошибочные расчёты оставлены в `data/ab_size*.md` с пометкой «заменён».
- Отчёт рисовал пересмотренный (действующий) вывод зачёркнутым, как отменённый — исправлено (`scripts/lib/report.py`).
- `ab_size.py` считал размер выборки только для роста доли — добавлен `--decrease` (`tests/test_analysis.py`).

**Пробелы, которые остались (и как их закрыть).** Частоты причин перебоев и связь перебоев с уходом номеров (данные оператора, T0 в Q1); тексты 126-ФЗ и 152-ФЗ (pravo.gov.ru отдал служебную страницу — нужен юрист); T2 и Yota (страницы отвечают HTTP 503/404); доля роутеров среди номеров владельцев. Реальных интервью нет — гайд v2 готов.
